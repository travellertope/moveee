# apps/cms — Payload CMS (replaces WordPress for editorial content)

Scope: **content only** — Articles, Newsletters, Quotes, and their taxonomies
(Categories, Industries/`culture_interest`, Series, Countries). Everything
else currently on WordPress (auth, gamification, follows, hubs, RSVPs,
commerce/WooCommerce) is out of scope for this app and stays on the WP
instance (or moves to a separate service later) — see the root `CLAUDE.md`
"How to move backend away from WordPress" discussion for the phased plan.

The collection configs in `collections/` already exist and mirror the exact
GraphQL fragments the Next.js apps currently read
(`packages/shared/lib/wp.ts` — `STORY_FIELDS_FRAGMENT`,
`NEWSLETTER_FIELDS_FRAGMENT`, `QUOTE_FIELDS_FRAGMENT`). What's *not* done yet
is the Next.js/Payload framework wiring itself (admin UI routes, REST/GraphQL
API route handlers) — that's best generated by Payload's own installer rather
than hand-written, since it's version-specific boilerplate.

## Setup on the new server (35.178.245.212)

Run these **on the server**, inside this repo, from `apps/cms/`:

```bash
# 1. Scaffold the Next.js + Payload framework files around the existing
#    collections/ and payload.config.ts (installer detects and preserves them)
npx create-payload-app@latest . --db postgres --editor lexical

# 2. Install the S3-storage plugin used by payload.config.ts for R2 media
npm install @payloadcms/storage-s3

# 3. Set env vars (.env in apps/cms/)
#    DATABASE_URI=postgres://...              (local Postgres on this box, or managed)
#    PAYLOAD_SECRET=<random 32+ char string>
#    R2_ACCOUNT_ID / R2_ACCESS_KEY_ID / R2_SECRET_ACCESS_KEY / R2_BUCKET_NAME
#      (same values as class-culture-r2.php's WP Admin fields)

# 4. First run — creates tables via Payload's migration system, prompts
#    for the first admin user
npm run dev
```

Admin UI will be at `http://35.178.245.212:3000/admin` (or whatever port —
put this behind Caddy/nginx with TLS before using it for real, same as the
WP instance should be).

## Migrating content from WordPress

Once the app is running, use Payload's Local API (not the REST API — faster,
no HTTP round-trip since the script runs on the same box) to bulk-import.
Fetch source data from the current WP GraphQL endpoint
(`https://cms.themoveee.com/graphql`) using the *exact same queries*
`wp.ts` already uses (`GET_STORIES`, `GET_NEWSLETTERS`, `GET_QUOTES`), map
each field 1:1 into the shapes above, and `payload.create({ collection, data })`
per record. Do this collection by collection (Categories/Industries/Series/
Countries/Authors/Media first, since Articles/Newsletters/Quotes reference
them), not all at once — easier to verify and re-run if one batch fails.

I can write this import script next once the app is actually running and you
have real `DATABASE_URI`/`PAYLOAD_SECRET` values — it needs a live Payload
instance to import into.

## Cutting the Next.js apps over

`packages/shared/lib/wp.ts`'s `getWPData()` is the single choke point both
`apps/site` and `apps/connect` fetch content through — once Payload is live,
add a `getPayloadData()` sibling function (Payload's REST or GraphQL API, or
even the Local API if apps/cms and the Next.js apps share infra) and swap
call sites one content type at a time (Quotes first — smallest fragment,
fewest cross-references — then Newsletters, then Articles last since it has
the most downstream consumers: magazine archive, homepage, newsletter
cross-links, mobile's `useMagazine.ts`).
