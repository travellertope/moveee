The Loom Keeps Time

Four hundred looms, eleven towns, and a counting system older than the cloth trade itself. Inside the archive trying to record every weave before the last people who can read them stop weaving.

The archive occupies two rooms above a hardware shop, and the first thing you notice is the noise it does not make. Four hundred looms are catalogued here, but none of them are in this building. What is here are the records: index cards, thread counts, photographs taken at a fixed distance so that any two cloths can be compared honestly.

Ifeoma Nwosu has run the project since 2019. Her method is unglamorous and entirely the point — every cloth is shot the same way, from the same height, under the same light, against the same grey card. The catalogue is the argument: put four decades of a single weaver's output in one grid and the drift becomes visible in a way no single photograph could show.

On methodSame height, same light, same grey card — so any two cloths in the archive can be compared honestly.

That drift is what the archive is really recording. A weaver working the same pattern for thirty years does not repeat it; the pattern moves with them. Nwosu calls the change "the hand showing" and treats it as data rather than error — which is why the catalogue photographs are so rigidly standardised.

You cannot see a decade in one cloth. You see it in forty, laid out in order, and then you cannot unsee it.
Wide · 1080

Reading a weave

Every cloth in the catalogue carries a six-part record: the town, the loom type, the warp count, the weeks of work, what it was made for, and whether anyone still weaves it. Those six fields are the reason the archive needed a table format at all — and the reason the table cannot live inside a 680-pixel column.

Two of the six rows above have no living practitioner. A third has three, all over seventy, in the same compound. Nwosu is careful not to call this preservation — the archive does not intervene, it records — but the funding applications say something closer to rescue.

How a cloth is recorded

Nwosu's intake procedure has not changed since the second year. It is written on a card taped inside the cupboard door, and every volunteer follows it in the same order.

  1. Measure before you touch. Length, width and selvedge depth, recorded in hand-spans first and centimetres second — never the other way round.
  2. Photograph at fixed distance. Same height, same grey card, same two lamps at 45°. No exceptions, no natural light, no "just this once".
  3. Count the warp. Twice, by two people, on separate days. A count that disagrees is re-run rather than averaged.
  4. Interview the weaver. Who taught them, what the pattern is called in their own town, and what it was made for.

What the card does not ask for

Four fields were tried and dropped. Each was removed for the same reason: it invited the recorder to interpret rather than record.

  • Quality grade — "there is no bad cloth, only cloth you don't understand yet"
  • Estimated market value, which moved faster than the archive could update it
  • Condition rating, replaced by a photograph of the damage itself
  • Regional style family, which turned out to be
    • inconsistently defined between towns, and
    • frequently disputed by the weavers themselves
The moment you write down what you think it means, that is the thing the next person reads instead of the cloth.

The counting system

Warp counts in the archive are recorded in threads per hand-span, not per centimetre, because that is how the weavers themselves count. Converting them would make the data tidier and the record less true. So the catalogue keeps both, side by side, and lets the reader do the arithmetic.

The last card in the catalogue is blank except for a town name and a date in 1974 — a cloth someone remembered but no one could produce. Nwosu keeps it in the drawer with the rest. "It counts," she says. "Knowing that we lost it is also a record."

Gutters collapse, not content

Below 1080px all three tiers resolve to one column at 18px inset. Nothing is hidden — .t-wide and .t-full simply stop differing from text.

Details scroll sideways

Stacked, the Details list costs 8 lines before the article starts. It becomes one horizontal row — grid-auto-flow: column over two rows, so each label/value pair gets its own column with no wrapper markup. Figure credits still drop inline under the block they annotate.

Galleries step, never shrink

6→3 and 3→2 columns. Cells keep a usable size instead of becoming thumbnails, which is what a fixed column count would do.

Tables keep every column

No column dropping, no card-per-row transform. Header and first column pin; the rest scrolls inside .tbl-wrap.

How it works

One CSS grid with named lines replaces the current fixed prose column. Everything defaults to the reading measure; galleries and tables opt out into a wider track. No wrappers, no negative margins, no JavaScript.

Text · default680px — body copy, headings, quotes
Wide · .t-wide1080px — galleries, tables, figures
Full · .t-full100% — bleed strips, one or two per piece
/* the whole system */
.ar-prose {
  display: grid;
  grid-template-columns:
    [full-start] minmax(20px, 1fr)
    [wide-start] minmax(0, 200px)
    [text-start] minmax(0, 680px) [text-end]
                 minmax(0, 200px) [wide-end]
                 minmax(20px, 1fr) [full-end];
}
.ar-prose > *          { grid-column: text; }  /* default */
.ar-prose > .t-wide    { grid-column: wide; }
.ar-prose > .t-full    { grid-column: full; }
.ar-prose > .t-note    { grid-column: wide-start / text-start; }

Authoring in WordPress

No shortcodes, no custom blocks, no editor training: the tiers map onto Gutenberg's existing alignment control. An editor selects a block, picks Wide or Full from the toolbar they already use, and the frontend resolves it to a track.

/* 1. WP side — makes Wide/Full appear in the block toolbar.
      culture-theme/functions.php (or theme.json settings.layout) */
add_theme_support( 'align-wide' );

/* 2. Frontend — map WP's own classes onto the tiers */
.ar-prose > .alignwide,
.ar-prose > figure.wp-block-table,        /* tables default wide */
.ar-prose > .wp-block-gallery            /* galleries default wide */
                        { grid-column: wide; }
.ar-prose > .alignfull  { grid-column: full; }
.ar-prose > .is-text-width
                        { grid-column: text; }  /* escape hatch */

/* 3. Gallery columns come straight from the block */
.wp-block-gallery.columns-2 { grid-template-columns: repeat(2, 1fr); }
.wp-block-gallery.columns-3 { grid-template-columns: repeat(3, 1fr); }
.wp-block-gallery.columns-6 { grid-template-columns: repeat(6, 1fr); }

/* 4. The Table block already ships its own <figure> wrapper —
      style that as the scroll box, no markup changes needed */
figure.wp-block-table { overflow-x: auto; }

The sidebar question

The current .ar-wrap is 1fr 300px, which caps the body at ~844px and makes a real breakout impossible. To get the wide tier, the Details card moves out of the right rail — either into the margin-note gutter, or a compact meta strip under the title.

Reading measure

Body copy narrows from 844px to 680px — closer to 65 characters. Text gets easier to read while images and tables get more room, not less.

Tables today

editorial.css has no table rules at all, so CMS tables render unstyled and overflow. This adds pinned header and first column, tabular numerals, and per-table horizontal scroll.

Already verified

class is in sanitize.ts's ALLOWED_ATTR, so alignwide/alignfull survive sanitising. Had it been stripped, this whole approach would silently collapse to one width.

Mobile

Under 1080px the gutters collapse to zero and all three tiers resolve to one column. Margin notes drop inline beneath their paragraph rather than disappearing.

What stays

Hero, title, standfirst, byline, breadcrumb and the floating TOC are untouched. This changes the body canvas only.
